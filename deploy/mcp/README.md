# MCP-коннектор PMO для GigaCowork

MCP-сервер даёт Коворку (cowork.gigab2b.ru) чтение и правку данных сайта
https://pmo.gigaenterprise.ai: проекты, опросники (включая доступы из модалок),
задачи по неделям, реестр миграций, требования, архитектуру.
Список пользователей сайта (email, статусы) через MCP **не отдаётся**.
Инструментов удаления **нет**.

- Адрес: `https://pmo.gigaenterprise.ai/mcp` (Streamable HTTP, без сессий)
- Проверка: `https://pmo.gigaenterprise.ai/mcp-health`
- Авторизация: заголовок `X-Api-Key` (или `Authorization: Bearer <ключ>`)

## Ключ доступа

Ключ создаётся при первом деплое (workflow `deploy-pmo-public.yml`) и в лог
Actions не выводится. Посмотреть его можно на сервере:

```bash
ssh user1@pmo.gigaenterprise.ai
cat /opt/pmo/mcp_api_key.txt
```

Ключ хранится в `/opt/pmo/deploy/.env` в переменной `MCP_API_KEYS`. Через
запятую можно указать несколько ключей, например чтобы сменить ключ без
простоя. После правки .env: `cd /opt/pmo/deploy && docker compose --profile mcp up -d mcp`.

## Форма «Создать коннектор» в Коворке

| Поле | Значение |
|---|---|
| Название | `PMO GigaEnterprise` |
| Описание | Проекты внедрения GigaChat/GigaCowork с сайта pmo.gigaenterprise.ai: какие проекты в работе, ответственные, сроки, статусы; опросники клиентов (ПАК/Гибрид), задачи по интеграции, данные для подключения к серверам (доступы, BMC, Nexus, токены); задачи по неделям и их статусы; реестр миграций; требования; архитектура. Использовать, когда спрашивают про проекты, клиентов, опросники, подключения, задачи недели или PMO. |
| Адрес сервера | `https://pmo.gigaenterprise.ai/mcp` |
| Тип аутентификации | **Пользовательские заголовки** |
| Заголовок | `X-Api-Key` = *ключ из /opt/pmo/mcp_api_key.txt* |
| Режим учётной записи | Единая учётная запись (ключ вводит администратор один раз для всех пользователей) |
| Инструкция по авторизации | Ключ выдаёт администратор PMO; его не нужно вводить каждому пользователю. |

Если в форме нет пользовательских заголовков, выберите «Токен доступа» и
вставьте тот же ключ: сервер принимает и `Authorization: Bearer`.

Серверам Коворка нужен сетевой доступ к `pmo.gigaenterprise.ai:443`.

## Инструменты

Чтение:
- `get_overview`: сводка по сайту
- `find_projects`: поиск и фильтры (статус, ответственный, продукт, приоритет, сроки, просрочка)
- `get_project`: карточка проекта
- `get_questionnaire`: опросник проекта
- `get_connection_details`: данные для подключения к серверам
- `find_questionnaire_gaps`: незаполненные обязательные поля опросника
- `get_week_tasks`: задачи и статусы за неделю
- `get_project_stats`: статистика по проектам
- `find_requirements`, `find_migrations`: требования и реестр миграций
- `get_architecture`: текст вкладки «Архитектура»
- `search_site`: поиск по всем страницам

Запись (без удаления):
- `create_project`, `update_project`
- `set_questionnaire_answer`
- `add_week_task`, `update_week_task`
- `update_requirement`, `update_migration`

Примеры вопросов в Коворке:
- «Какие проекты сейчас в работе и кто ответственный?»
- «Выведи задачи по интеграции и списком данные для подключения к серверам»
- «Какой статус задач по проектам на этой неделе?»

## Одновременная правка

Каждый ключ в базе (`kv_store`) хранит версию. Сайт и MCP сохраняют данные
только поверх той версии, которую видели. Если кто-то успел сохранить раньше,
изменения сливаются по строкам и полям: правки разных людей в разных полях
сохраняются все. Открытые страницы раз в 15 секунд подтягивают чужие изменения
без перезагрузки. MCP пишет в транзакции с блокировкой, поэтому параллельные
вызовы из Коворка тоже не затирают друг друга.
