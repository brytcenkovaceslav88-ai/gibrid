# Деплой PMO backend на сервер (159.194.227.150 / pmo.qslaide.beget.tech)

## Что тут лежит
- `docker-compose.yml` — Postgres + backend (Node/Express + Better Auth) + Nginx + автопродление HTTPS
- `backend/` — заготовка backend-сервиса
- `nginx/` — два конфига (bootstrap для первого запуска, full — после выпуска сертификата)
- `setup-server.sh` — пошаговый скрипт разворачивания
- `.env.example` — шаблон переменных окружения

## Порядок действий

Пакет уже полностью готов к запуску: `frontend/index.html` (собранный фронтенд) и `.env`
(со сгенерированными `POSTGRES_PASSWORD` и `BETTER_AUTH_SECRET`) уже лежат внутри — заполнить
руками нужно только реальные данные SMTP (см. ниже), они не критичны для первого запуска.

1. **Скопировать содержимое папки `deploy/` на сервер**, в `/opt/pmo/`
   (например через веб-файловый менеджер Beget: загрузить zip и распаковать,
   либо `scp -r deploy root@159.194.227.150:/opt/pmo` со своей машины)
2. Зайти на сервер по SSH и выполнить:
   ```
   cd /opt/pmo
   chmod +x setup-server.sh
   ./setup-server.sh
   ```
3. Скрипт сам проверит DNS домена `pmo.qslaide.beget.tech`:
   - если DNS ещё не указывает на этот сервер — поднимет сайт по обычному HTTP и остановится
     с понятным сообщением, что нужно поправить в Beget
   - если DNS уже в порядке — сразу выпустит сертификат Let's Encrypt и включит HTTPS
4. После правки DNS в Beget (см. ниже) просто запустите `./setup-server.sh` ещё раз —
   шаги установки Docker и запуска контейнеров пропустятся, сразу перейдёт к сертификату
5. Финальная проверка: `https://pmo.qslaide.beget.tech/api/health` должно вернуть `{"ok":true}`

## Что нужно сделать отдельно перед реальным использованием
- **DNS (блокирует HTTPS и открытие сайта по домену)**: сейчас A-запись `pmo.qslaide.beget.tech`
  указывает на `5.101.153.31`, а не на выданный сервер `159.194.227.150`. Нужно поменять
  A-запись в панели управления доменом (Beget) на `159.194.227.150`, обновление обычно
  занимает 5–30 минут.
- **Почта на домене** для SMTP (подтверждение почты / сброс пароля). Проще всего — Яндекс 360
  для домена (бесплатно на небольшое число ящиков): нужно добавить MX/SPF-записи в DNS домена
  `qslaide.beget.tech`. Пока в `.env` стоят условные значения — регистрация/сброс пароля не
  будут отправлять письма, пока их не заменить на настоящие.

## Честно про то, что нестопроцентно проверено
Я собрал этот пакет по документированным, стандартным паттернам (Docker Compose + Certbot
webroot + Better Auth) и вручную нашёл и исправил один реальный баг (entrypoint контейнера
certbot глушил команду выпуска сертификата), но **выполнить `setup-server.sh` вживую на этом
сервере я не смог** — облачное окружение, в котором я работаю, блокирует исходящие SSH-подключения
(порт 22) на уровне сети; порт 80 того же сервера при этом открывается нормально, то есть дело
не в вашем сервере или пароле, а в ограничении моей текущей среды выполнения. Точки, которые
стоит перепроверить при первом реальном запуске:
- Точные названия полей конфига Better Auth (`emailAndPassword`, `emailVerification`) — библиотека
  активно развивается, к моменту запуска могли появиться небольшие изменения API. Актуальная
  документация: https://www.better-auth.com/docs
- Версия `better-auth` в `package.json` (`^1.2.0`) — стоит проверить актуальную на npm перед
  `npm install`

## Безопасность — сделать сразу после первого успешного запуска
- Сменить пароль root (тот, что был прислан в чат, лучше считать скомпрометированным)
- Настроить вход по SSH-ключу, отключить вход по паролю
- `ufw allow 22,80,443/tcp && ufw enable`
