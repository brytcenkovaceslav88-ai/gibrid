# Деплой PMO на сервер (159.194.227.150 / pmo.qslaide.beget.tech)

## Что тут лежит
- `docker-compose.yml` — Postgres + backend (Node/Express) + Nginx + автопродление HTTPS
- `backend/` — backend-сервис: авторизация с подтверждением админом + общее хранилище данных таблиц
- `nginx/` — два конфига (bootstrap для первого запуска, full — после выпуска сертификата)
- `setup-server.sh` — пошаговый скрипт разворачивания
- `.env.example` — шаблон переменных окружения

## Авторизация
Простая схема без email-подтверждения:
1. Новый посетитель видит форму регистрации (email + пароль).
2. Первый зарегистрированный аккаунт автоматически становится администратором и активируется сразу.
3. Все следующие регистрации попадают в статус «ожидает подтверждения» — доступа к сайту у них нет.
4. Администратор в панели «👤 Пользователи» (кнопка в шапке сайта) активирует/блокирует пользователей и может сменить любому пароль.
5. Данные таблиц (`/api/data/:key`) доступны только активным пользователям.

## Автодеплой
После пуша в эту ветку (изменения в `index.html` или `deploy/**`) GitHub Actions
(`.github/workflows/deploy.yml`) сам копирует обновлённые файлы на сервер и
перезапускает контейнеры — вручную `scp`/`ssh` для этого делать не нужно.

## Порядок действий (первый запуск)

1. Скопировать содержимое папки `deploy/` на сервер в `/opt/pmo/`
2. `cp .env.example .env`, сгенерировать `BETTER_AUTH_SECRET` (`openssl rand -base64 32`) и задать пароль Postgres
3. На сервере:
   ```
   cd /opt/pmo
   chmod +x setup-server.sh
   ./setup-server.sh
   ```
4. Скрипт сам проверит DNS домена и либо поднимет сайт по HTTP (если DNS ещё не указывает
   сюда), либо сразу выпустит сертификат Let's Encrypt и включит HTTPS
5. Проверка: `https://pmo.qslaide.beget.tech/api/health` → `{"ok":true}`

## Безопасность — сделать сразу после первого успешного запуска
- Сменить пароль root (тот, что был прислан в чат, лучше считать скомпрометированным)
- Настроить вход по SSH-ключу, отключить вход по паролю
- `ufw allow 22,80,443/tcp && ufw enable`
