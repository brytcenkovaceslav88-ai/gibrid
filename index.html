Полное описание архитектуры платформы: границы системы, диаграммы C4 и справочные таблицы.

Границы системы

Система отвечает за:

  • приём, маршрутизацию и обработку пользовательских запросов
  • запуск и выполнение агентных сессий
  • стриминг событий агентной сессии в UI
  • хранение и управление документами, файлами рабочих пространств, RAG-поиском
  • аутентификацию и авторизацию пользователей
  • маршрутизацию вызовов к внешним инструментам и коннекторам через MCP-контур
  • управление рабочими пространствами: участники, роли, права доступа, документы и настройки

Система не отвечает за:

  • непосредственную генерацию LLM-ответов на уровне модели
  • владение корпоративной identity-инфраструктурой заказчика: IdP остаётся внешней системой, платформа интегрируется с ним по OIDC/OAuth2
  • владение OAuth-провайдерами сторонних SaaS: авторизация в коннекторах выполняется на стороне Albato/соответствующего SaaS, платформа только инициирует и маршрутизирует connector-flow

Как читать эту таблицу

Соответствие (шкала 1–4)

  • 4 — полностью поддерживается
  • 3 — частично / с ограничениями
  • 2 — требует доработки / кастомной интеграции
  • 1 — не поддерживается

Остальные чипсы

  • Раздел — из какого из 10 листов исходного файла (13 категорий) взято требование; отдельный цвет на категорию, фильтруется через 🔽 в шапке колонки
  • Решающее — критично для приёмки; Не решающее — желательно, но не блокирует
  • Двойной клик по любой ячейке — редактирование; для чипсов открывается список, для остальных — обычный текст

Что умеет GigaCowork

  • Российская платформа, входит в реестр отечественного ПО; техподдержка на русском языке (email, телефон), база знаний для пользователей
  • No-code конструктор ассистентов с графическим интерфейсом + гибридный режим разработки (Python-код там, где нужна кастомная логика)
  • Контроль версий и A/B-тестирование ассистентов, параллельная работа нескольких ассистентов на одной модели
  • Мультиагентные системы: оркестрация нескольких моделей и агентов, параллельное выполнение задач разного типа данных
  • Поддержка MCP (Model Context Protocol) для подключения внешних инструментов и сервисов
  • Встроенный Model Serving Framework — endpoint'ы predict / load_model для инференса моделей
  • Готовая интеграция LLM, Embedding, ASR и TTS моделей; визуальные, видео- и часть аудио-моделей — через кастомную интеграцию
  • Конструктор логики агентов: If/Else, Switch, Parallel, Wait; запуск цепочек по расписанию и по событию
  • RBAC, аудит всех действий, локализация данных на территории РФ (152-ФЗ), мониторинг и журналирование инцидентов
